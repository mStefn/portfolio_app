01 — Overview

Turning a personal PC into a local AI environment

This project started as an experiment with running language models locally and evolved into a small self-hosted environment for AI-assisted development.

The machine runs a headless Arch Linux installation directly on bare metal and uses an NVIDIA RTX 2070 Super with 8 GB of VRAM for GPU-accelerated workloads.

Instead of relying entirely on external AI services, the environment allows me to run models locally, work with project-specific context and use AI tools directly against code and infrastructure repositories.

04 — Hardware Constraints

The 8 GB VRAM problem

Running local AI on an RTX 2070 Super changes the way the system has to be used. The main limitation is not API cost — it is available hardware resources.

Problem

The GPU has only 8 GB of VRAM, while model size and context directly influence memory consumption.

Solution

Models and workloads have to be selected according to the actual hardware rather than simply choosing the largest available model.

Result: predictable local inference within the limits of the machine.

Problem

Feeding an entire repository into the model can consume context unnecessarily and reduce the usefulness of the available context window.

Solution

Work is organized around a specific project, relevant files and a dedicated system prompt instead of sending everything at once.

Result: more focused AI-assisted development.

Problem

AI workloads compete for the same limited GPU, RAM and system resources as the rest of the server.

Solution

GPU and system resource monitoring is treated as part of normal operation rather than an optional extra.

Result: workloads can be adjusted based on the actual state of the machine.

11 — Lessons Learned

What the project taught me

Local AI is not only a model-selection problem. Hardware limitations directly affect how the system has to be used.
More context is not automatically better. Relevant context is often more useful than sending an entire project to the model.
GPU and system resource monitoring becomes part of normal operation when hardware resources are limited.
Running AI locally requires a properly configured operating system, drivers, dependencies and services.
A dedicated project workspace makes local AI-assisted development easier to organize and repeat.
Self-hosting turns hardware constraints into an actual engineering problem instead of hiding them behind a cloud platform.

A local AI system built around real constraints

This project combines Linux administration, GPU workloads, local AI inference and AI-assisted development into one self-hosted environment. The main challenge is not simply making a model run, but making the available hardware useful.
